Before you enable one

A model provider reads document text, which makes them a processor under Article 28 for every tenant whose documents it touches. Update the DPA, the subprocessor list and the transfer assessment before switching one on — that is why this control sits with the platform operator and not with individual suppliers.

Special-category documents are excluded from AI processing entirely, whichever provider is active.

A self-hosted OpenAI-compatible endpoint keeps document text inside your own boundary and removes the subprocessor question.

How keys are held

At rest
Encrypted with a key derived from SECRET_KEY
In the UI
Mask and fingerprint only, never the key
In the log
Fingerprint only, on every create, change and delete
On delete
Ciphertext destroyed with the row
Rotating SECRET_KEY makes every stored key unreadable. The provider will report a decryption failure and fall back to rules until the key is re-entered.

This protects a stolen database file or backup. It does not protect against someone holding both the database and SECRET_KEY — the application must be able to decrypt in order to make a call. A production deployment stores these in a KMS and keeps only a reference here.
